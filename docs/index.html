Methodology

Our Approach

Each alert has a 180-day transaction history. We engineer alert-level features, then select them by cross-validated measurement — not intuition.

📊 Feature Engineering

Nine feature families were built from transaction history: direction counts, type amounts, flow ratios, time windows, burst patterns, and signal date features. Each family was evaluated independently via greedy forward search judged on 5-fold CV repeated 4 times.

→ Only 2 families survived the search — direction_type and base

🎯 Model Ensemble

Four models (LightGBM, XGBoost, CatBoost, LogReg) were tuned via Optuna with mean − std scoring. Rank averaging with OOF-fitted weights produces the final blend. Equal weights are used unless fitted weights beat them by ≥0.001 AUC.

✓ Adversarial AUC = 0.4956 → train/test indistinguishable
Exploratory Data Analysis

Transaction Patterns

Key visualizations that informed our modeling decisions.

📈 Activity Before Alert

Transaction volume accelerates sharply in the final 5 days before an alert triggers — escalated alerts show an even steeper spike. This temporal burst is the strongest raw signal.

→ Escalated alerts show 3× activity surge in final 5 days

📊 Transaction Type Distribution

Card transactions dominate the dataset. Incoming transfers (kirim) contain the bulk of volume, while outgoing (chiqim) patterns differ significantly between outcomes.

🎯 Target Distribution

Only 2.1% of alerts are escalated — a heavily imbalanced binary classification problem. This extreme class skew makes raw accuracy misleading; ROC-AUC properly measures ranking quality regardless of threshold choice.

⚠ Severe class imbalance — probability-based scoring essential

🔄 Incoming vs Outgoing by Outcome

Amount distributions across direction (kirim/chiqim) and type carry the strongest predictive signal. Raw counts provide almost no discrimination — it's the how much, not how many.

✓ Per-direction amount stats = strongest feature family

Summary

Conclusion

Key Takeaways

Base features — transaction type and direction — carry the strongest signal. Time-window and complex aggregations introduced noise and led to overfitting. Cutting features raised accuracy, not lowered it.

Escalated alerts are characterized by a sharp burst of specific transactions in the days immediately preceding the trigger. Based on these insights, we conducted strict feature selection, removed noisy variables, and built a robust ensemble that guarantees stability on the hidden test set.

The binding constraint is variance, not capacity. Every choice pushes the same direction: regularization-biased hyperparameter search, bagging over multiple seeds, and equal-weight rank averaging unless fitted weights prove significantly better.
